Notes
1. The cached reading (no-clear-snapshot). PostgreSQL keeps the first reading of pg_stat_activity for the rest of the transaction. The first version of the second check, without the
   pg_stat_clear_snapshot() that now opens it, saw exactly what the first check had seen and let the file through (A14 was red on it before the fix); with it, the check sees the login
   that connected in between. A8 (iii) alone would not have shown this: the text was there.
2. R-DB-12 (the header said a second run asks for no stronger lock). The choice was to correct the text, not to guard steps 2 to 6 with a catalog check. A12 has a third phase that keeps
   the text true: a reader of intake_thread_heads waits for the second run (55P03); there is no mutant for it, the phase is a fact about the file, not a rule that a change could break
   silently.
3. R-S-10 (the order of the two locks at step 1) is a sentence in the header only: no code or case changed.
