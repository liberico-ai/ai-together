Each of the three conditions added to the catalog check is killed by its own variant of B11b and by no other: none of them is redundant, and none is equivalent. Not covered by a case: a
numbering trigger recreated BEFORE INSERT or at statement level (other values of tgtype, refused by the same condition tgtype = 5; B11b has the AFTER UPDATE variant for that condition).
The function dropped with its trigger (DROP FUNCTION ... CASCADE) is the case "dropped" of B11: the trigger is gone, and to_regprocedure answers null, not an error.
A16 and A15 stand for two different things and each has its own mutant: A16 pins who holds the lock at step 1 (a first application does not, a second run does), A15 pins that the lock of a
second run is there when a raw confirmation meets the file (native only: two sessions and the lock queue); on pglite only A16 and the static order of A8 (iii) go red for a missing lock.
