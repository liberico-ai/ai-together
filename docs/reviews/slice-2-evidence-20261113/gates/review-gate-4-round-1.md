### New Breakage in the Fix Diff
None Critical or Important.
- Minor: `Spool._commit` appends to the dead-letter file, then rewrites the spool. A crash between the two cannot lose a line, but on the next drain the line is retried and can be dead-lettered a second time (duplicate dead entry, at-least-once). Same ordering means no atomic cross-file move; acceptable, worth a one-line comment.
- Minor: `_commit` runs in `finally` and can raise `SPOOL_BUSY` after sends succeeded; the exception replaces the original and the sent lines stay in the spool, so they are replayed later (harmless, the backend keys by chat and message id).
- Minor: worst-case wall time per hook call is about 5x2 s + 2 s network plus up to ~1 s per lock wait (drain commits, put). This matches the ruling's counts but is not a hard cap on total time.
- Minor: `attempts` counts every answered 5xx, so a backend outage that answers 503 across 5 hook calls dead-letters the head event(s) (not lost: kept in `intake-dead.jsonl`, owner-only). This follows the ruling as written.
- Minor: `SPOOL_LINE_UNREADABLE` dead entries store the raw line (may hold message text) in the owner-only 0600 file. Acceptable; never logged.

Named risks: dead-letter move cannot lose or duplicate within one commit (checked under the lock against `current[:len(consumed)]`; a concurrent drain that settled the same lines makes the second a no-op, so no double dead entry from concurrency). No SPOOL_BUSY from a leak: the fd is closed in `finally`, there is no nested lock acquisition (put runs after drain returns), and `LOCK_NB` retries only against a real holder. Logging: only fixed codes and literal field names are added; no text, ids, names or codes. Frozen originals: the first changed test hunk starts at test line 113 (`git diff -U0`), so lines 1-110 are untouched; the changed file list is only `bot-plugin/__init__.py` and `tests/test_bot_bridge.py`, so VERSION and plugin.yaml are unchanged.
